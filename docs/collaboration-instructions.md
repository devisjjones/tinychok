# Collaboration Instructions

Короткая памятка по тому, как давать владельцу проекта ручные инструкции и как формулировать проверки.

## Формат Ручных Инструкций

- если действие должен выполнять человек, инструкции разбиваются на отдельные блоки `Шаг 1`, `Шаг 2`, `Шаг 3`
- один шаг должен описывать один логический кусок действий
- если нужна визуальная проверка, после нужного шага нужно просить скриншот
- если проверка зависит от UI-состояния, полезно просить скрин сразу после ключевого действия, а не только в самом конце

## Когда Просить Жёсткое Обновление

- после правок иконок
- после правок аватаров
- после обновлений emoji picker, GIF picker и другой свежей статики
- после изменений viewer-а, шрифтов и локальных asset-файлов

## Как Проверять Server-Driven UI

Если механика завязана на snapshot, realtime или lazy history, полезно просить отдельные скрины:

- сразу после входа в комнату
- после скролла вверх и догрузки истории
- после reload страницы

Это помогает отделять локальный optimistic state от реально сохранённого server state.

## Как Проверять Delete Flow

Delete-path нельзя считать проверенным только по исчезновению элемента из UI.

Нормальный сценарий проверки:

1. удалить сообщение или пост;
2. выйти из комнаты;
3. зайти в комнату снова;
4. при необходимости сделать hard reload;
5. только после этого считать delete-path починенным.

## Как Проверять Media Flow

Для фото, файлов, GIF и viewer-а полезно просить отдельные скрины:

- preview до отправки
- сообщение после отправки в ленте
- fullscreen viewer после tap
- ошибка при oversized / unsupported file, если проверяется validation path

## Как Проверять Premium Flow

Если проверка касается premium, всегда полезно уточнять:

- premium включён или выключен
- тестируется locked-state или unlocked-state
- используется ли debug purchase layer

Debug-механизмы и ограничения production rollout описаны отдельно в [docs/debug-flags.md](/Users/devisjones/Documents/New%20project/tinychok/docs/debug-flags.md).

## Ограничения И Безопасность

- не просить присылать в чат секреты, пароли, `.env` или содержимое `htpasswd`
- если нужен результат команды с секретами, просить только безопасный фрагмент или скрин без секретных значений
- при ссылках на `сегодня`, `вчера`, `после полуночи` использовать точные даты, если это влияет на понимание бага

## Контекст Staging

- `staging.tinychok.ru` закрыт через basic auth
- backend staging ограничен allowlist-ом телефонов
- при любых ручных проверках staging нужно учитывать оба этих ограничения доступа
